Prompt Workbench is a local developer tool to create, version, test, compare and publish LLM prompts and linear prompt chains — then export them as ordinary files any language can load.

Start the demo See the architecture

“Version control for prompts, an evaluation table for comparisons, and a portable release bundle — with no cloud account.”

What it is

A single, self-hosted app that treats prompts like real software artifacts.

The problem

Prompts live scattered in code and notebooks. There is no history, no way to A/B two revisions on the same examples, and no safe way to promote “the version we actually tested” to production.

The workbench

Immutable, numbered revisions with change notes and diffs. Named datasets of examples. A comparison matrix across models with checks, tokens, latency and cost. Portable release bundles that run with the workbench stopped.

Features

Everything you need to iterate on prompts with confidence.

🗂️

Registry & versioning

Stable UUIDs, immutable numbered revisions, change notes, diffs, restore, and static development/staging/production labels.

🧩

Strict templating

The tiny simple-v1 engine: typed {{variables}}, JSON-Schema validation, deterministic rendering. No code execution, ever.

📊

Evaluations

Compare candidates on identical dataset snapshots with deterministic checks, pass/fail gates, latency and cost — separating execution from quality.

🔗

Linear chains

Ordered steps with typed bindings between them, per-step model overrides, and step-level testing with frozen upstream fixtures.

📦

Portable releases

Publish a hash-verified bundle of exact prompt + model configs. Load it from Python or any language — no database, no workbench.

📥

Capture intake

Ingest production examples over a scoped, idempotent API and promote them into regression datasets — without granting publish access.

How it works

The core loop, from idea to production file.

Author

Write a prompt with typed variables in the editor; preview the render live.

Save a version

Freeze an immutable revision with a change note and content digest.

Compare

Run candidates over a dataset and read the scored matrix.

Label

Point production at the revision you trust.

Publish

Export a verified, self-contained release bundle.

Architecture — modular by design

Swappable components behind clean interfaces. Two decisions that matter most:

Pluggable storage

Everything talks to one Repository interface. MongoDB is the primary/production backend; a zero-dependency SQLite backend powers the offline demo and tests. Swap with one setting.

MongoRepositorySqliteRepository

Pluggable AI services

Every model call goes through a ModelProvider. A deterministic mock provider runs fully offline; a LiteLLM provider reaches OpenAI, Anthropic, Gemini, Ollama, Azure and OpenAI-compatible endpoints.

MockProviderLiteLLMProvider

Backend

Python · FastAPI · Pydantic v2 · async storage · Argon2id + JWT auth · Typer CLI.

Frontend

React · TypeScript · Vite · TanStack Query — a dense, keyboard-friendly developer UI.

Runtime

A separate dependency-light package that loads and renders release bundles anywhere, plus a JavaScript reference renderer.

Quickstart

Explore a fully seeded workspace in under a minute — no keys, no cloud, no external database.

# 1. install the backend
pip install -e backend

# 2. launch the demo (SQLite + mock models)
prompt-workbench demo

# open http://127.0.0.1:8765
# login: demo@promptworkbench.dev / workbench
The demo is entirely synthetic. It never contacts a paid provider and clearly labels all data as example content.
